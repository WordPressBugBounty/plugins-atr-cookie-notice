באנר הסכמה לעוגיות המתאים לחוק הגנת הפרטיות בישראל (תיקון 13).

== Description ==

**ATR Cookie Notice** הוא תוסף ניהול הסכמה לעוגיות חזק וידידותי למשתמש המיועד לסייע לאתרי WordPress ליישר קו עם חוקי הגנת הפרטיות בישראל (כולל תיקון 13) ובמדינות נוספות, ועם פרקטיקות פרטיות מקובלות. לתוסף שני מצבים: מלא (מנטרל את Google Analytics ו‑Facebook Pixel עד להסכמה, עם אפשרויות הסכמה מפורטות ובאנר מותאם אישית; קוד מעקב מהתבנית צריך עטיפה, ראו "חשוב" בהמשך) ופשוט (ללא חסימה, מידע בלבד).

**תיעוד:** [התיעוד המלא](https://atarimtr.co.il/atr-cookie-notice-docs/) · [מדיניות פרטיות לדוגמה](https://atarimtr.co.il/atr-cookie-notice-sample-privacy-policy/) · [מדריך בדיקות](https://atarimtr.co.il/atr-cookie-notice-testing-guide/)

### תכונות עיקריות

* **מוכוון חוק ישראלי** - מיועד ליישור קו עם חוק הגנת הפרטיות (כולל תיקון 13)
* **בקרת עוגיות מפורטת** - אפשרויות הסכמה נפרדות לעוגיות חיוניות, אנליטיקה ושיווק
* **עיצוב מותאם אישית** - שליטה מלאה בצבעים, מיקום ועיצוב עם בוררי צבעים של WordPress
* **תוכן מותאם אישית** - שליטה מלאה בטקסט הבאנר, כפתורים ופוטר HTML עם תמיכה בטוקנים
* **מיקומי באנר מרובים** - אפשרויות מיקום בתחתית, למעלה או כשכבת-על במרכז
* **פונקציונליות הסתרה אוטומטית** - סגירה אוטומטית אופציונלית של הבאנר
* **תמיכה ב-RTL** - תמיכה נכונה בשפות מימין לשמאל
* **עיצוב רספונסיבי** - עובד בצורה מושלמת בכל המכשירים וגדלי המסך
* **תמיכה רב-לשונית** - תרגומים מובנים לעברית ואנגלית
* **ידידותי למפתחים** - הוקים ופילטרים נרחבים להתאמה אישית
* **אינטגרציה עם מדיניות פרטיות** - ניהול מובנה של מדיניות פרטיות
* **ניהול תפוגת עוגיות** - משך הסכמה ניתן להגדרה
* **מצב דיבוג** - כלי פיתוח לבדיקה ופתרון בעיות
* **מצבי הסכמה** - בחירה בין מלא (מנטרל את הפונקציות של Google Analytics ו‑Facebook Pixel עד להסכמה; קוד מעקב מהתבנית צריך עטיפה, ראו "חשוב" למעלה) לפשוט (מידע בלבד)
* **כלים** - כפתור "ניקוי מטמון ורענון משאבים" בלחיצה אחת עם cache busting, איפוס עיצוב לברירת מחדל

### חשוב: קוד מעקב שהתבנית או תוסף אחר מוסיפים

מצב מלא מנטרל את הפונקציות של Google Analytics ו‑Facebook Pixel עד להסכמה, אבל **לא עוצר קוד מעקב שהתבנית או תוסף אחר מדפיסים לתוך הדף** (למשל קוד Google Tag Manager ב‑header, או קוד שנוסף בתוסף "הוספת קוד ל‑header/footer"). קוד כזה רץ לפני שהמבקר מחליט.

כדי להעביר קוד כזה לשליטת הבאנר, עוטפים אותו בסימון ההסכמה של התוסף. משנים רק את תגית ה‑`<script>` הפותחת:

    <script type="text/plain" data-consent="analytics">
      ... קוד Google Tag Manager / Analytics ...
    </script>

    <script type="text/plain" data-consent="marketing">
      ... קוד Facebook Pixel / פרסום ...
    </script>

הדפדפן לא מריץ סקריפט מסוג `text/plain`. אחרי שהמבקר מסכים לקטגוריה, התוסף הופך אותו לסקריפט רגיל ומריץ אותו; אם המבקר דוחה, הוא לא רץ אף פעם. זה עובד לקוד ישיר ולסקריפטים עם `src`, בכל מקום שבו הם מודפסים (header של התבנית, `wp_head`, תוספי הוספת קוד, בוני עמודים). קוד שקובץ JavaScript אחר יוצר בזמן ריצה לא מכוסה. את חלקי ה‑`<noscript>` של Google Tag Manager ו‑Facebook Pixel (iframe או תמונה בגוף הדף) אי אפשר לעטוף: הם נטענים רק כש‑JavaScript כבוי, כשאין באנר שיכול לבקש הסכמה, ולכן יש למחוק אותם.

### קטגוריות עוגיות

התוסף מנהל שלוש קטגוריות עוגיות עיקריות:

1. **עוגיות חיוניות** - תמיד מופעלות, נדרשות לתפקוד בסיסי של האתר
2. **עוגיות אנליטיקה** - אופציונליות, לאנליטיקה של האתר וניטור ביצועים
3. **עוגיות שיווק** - אופציונליות, לפרסום ומטרות שיווק

### אפשרויות התאמה אישית

* **CSS מותאם אישית** - הוסיפו כללי עיצוב משלכם
* **התאמת תוכן** - התאימו טקסט באנר, כפתורים ופוטר HTML עם תמיכה בטוקנים ({site_name}, {privacy_url}, {privacy_link})
* **פריסטים לעיצוב** - פריסטים של בהיר, כהה, מינימלי, ניגודיות גבוהה להגדרה מהירה

* **תקני קידוד WordPress** - עוקב אחר WPCS ופרקטיקות מומלצות
* **הוקים נרחבים** - התאמה אישית של התנהגות עם פעולות ופילטרים של WordPress

מושלם עבור עסקים, סוכנויות ומפתחים הזקוקים לפתרון ניהול הסכמה לעוגיות אמין המיושר עם הדין הישראלי ושניתן להתאים בקלות לכל עיצוב אתר.

== התקנה ==

1. העלו את קבצי התוסף לתיקייה `/wp-content/plugins/atr-cookie-notice`, או התקינו את התוסף דרך מסך התוספים של WordPress ישירות.
2. הפעל את התוסף דרך מסך 'תוספים' ב-WordPress
3. עברו להגדרות → **ATR Cookie Notice** כדי להגדיר את התוסף
4. סמנו **הפעל באנר עוגיות** כדי להציג את הודעת העוגיות למבקרים
5. התאימו את מראה הבאנר, ההתנהגות וקטגוריות העוגיות לפי הצורך
6. השתמשו בתצוגה המקדימה החיה כדי לראות שינויים בזמן אמת
7. הקישו **שמור הגדרות** כדי להחיל את השינויים שלך
8. באנר העוגיות יופיע אוטומטית בחזית האתר שלך

== שאלות ותשובות ==

תשובות נוספות, עם הסבר צעד אחר צעד: [שאלות נפוצות ופתרון בעיות](https://atarimtr.co.il/atr-cookie-notice-docs/#faq).

= האם צריך להגדיר משהו לאחר ההתקנה? =

התוסף עובד כברירת מחדל במצב מלא עם הגדרות בסיסיות. מומלץ להתאים את המראה, קטגוריות העוגיות, ואם צריך – לשנות את מצב ההסכמה ל"פשוט" (מידע בלבד). בדף הגדרות התוסף ניתן להגדיר צבעים, מיקום, קטגוריות ומצב ההסכמה.

= האם התוסף מסייע לעמידה בחוק הישראלי? =

ATR Cookie Notice מיועד לסייע ליישור קו עם חוק הגנת הפרטיות בישראל (כולל תיקון 13). במצב מלא ניתן להציג קטגוריות מפורטות, לתעד הסכמה ולנטרל את Google Analytics ו‑Facebook Pixel עד לאישור. קוד מעקב שהתבנית או תוסף אחר מוסיפים לא נחסם אוטומטית, וצריך לעטוף אותו (ראו "חשוב" בתיאור). מצב פשוט הוא מידע בלבד ואינו חוסם עוגיות לא‑חיוניות. אינו מהווה ייעוץ משפטי – בדוק/י את דרישותיך מול גורם משפטי.

= האם ניתן להתאים את מראה באנר העוגיות? =

בהחלט! התוסף מציע אפשרויות התאמה אישית נרחבות כולל בוררי צבעים של WordPress עם תצוגה מקדימה חיה, מיקום, CSS מותאם אישית ופריסטים לעיצוב (בהיר, כהה, מינימלי, ניגודיות גבוהה). אתה יכול גם להתאים את טקסט הבאנר, הכפתורים ופוטר ה-HTML באמצעות טוקנים כמו {site_name}, {privacy_url} ו-{privacy_link}.

= מהם הטוקנים הזמינים לתוכן? =

אתה יכול להשתמש בטוקנים הבאים בטקסט באנר מותאם אישית ובפוטר HTML:
* {site_name} - שם האתר שלך
* {privacy_url} - כתובת URL של דף מדיניות הפרטיות
* {privacy_link} - תג anchor מלא עם קישור למדיניות הפרטיות
* [ok_button] - כפתור אישור (מצב פשוט)
* [accept_all_button] - כפתור קבל הכל (מצב מלא)
* [reject_button] - כפתור דחה (מצב מלא)
* [preferences_button] - כפתור העדפות (מצב מלא)
* [privacy_link] - קישור למדיניות פרטיות (מצב פשוט)


= צבעי הכפתורים נראים אחרת בגלל התבנית =

הפעילו אפשרויות מתקדמות ← "Force override theme styles". הבאנר ישתמש בכללים חזקים יותר מה־CSS של התבנית.

= פופאפ של האתר מסתיר את באנר העוגיות =

העלו את עיצוב ומראה ← "Banner Z-Index". הערך המרבי הוא 2147483647, והוא מציב את הבאנר מעל כמעט כל רכיב. המבקרים יכולים גם לגרור את הבאנר הצידה בעזרת הידית בראשו (גרירה אינה הסכמה).

= הבאנר לא מופיע ב‑Brave או עם חוסם פרסומות =

Brave (חסימת הודעות עוגיות ב‑Shields), uBlock Origin ו‑AdGuard יכולים להשתמש ברשימת הסינון הציבורית "EasyList Cookie", שחוסמת קובצי הודעות עוגיות לפי שם. קובצי ה‑CSS וה‑JavaScript של התוסף נחסמים, ולכן הבאנר לא מוצג. זו בחירה של המבקר. המבקר לא מסכים אף פעם, ולכן סקריפטים שעטופים ב‑`data-consent` לא רצים אצלו. ה‑HTML של הבאנר נשאר מוסתר, כך שלא מופיעים כפתורים בלי עיצוב. כדי לבדוק את הבאנר, השתמשו בדפדפן בלי חוסמים כאלה, או כבו את החוסם לאתר שלכם.

= האם התוסף תומך במספר שפות? =

כן, התוסף כולל תמיכה מובנית בעברית ואנגלית. תרגומים נוספים יכולים להיות מוספים דרך מערכת התרגום של WordPress.

= איך מתרגמים טקסט באנר מותאם באתר רב־לשוני (WPML / Polylang)? =

להגדרות התוסף יש סט אחד לכל האתר. החלפת דגל השפה בסרגל הניהול לא שומרת עותק נפרד לכל שפה. שדות התוכן (טקסט, פעולות ופוטר) רשומים לתרגום דרך `wpml-config.xml`:

1. כותבים את הטקסט בהגדרות ← ATR Cookie Notice ← תוכן, בשפת ברירת המחדל של האתר, ושומרים.
2. מתרגמים לפי המדריך של התוסף הרב־לשוני:
   * WPML: [Registering strings from the admin area and plugin settings](https://wpml.org/documentation/translating-your-contents/strings/finding-strings-that-dont-appear-on-the-string-translation-page/#register-admin-and-setting-strings-for-translation) - במסך Admin Texts מחפשים את `atr-cookie-notice`.
   * Polylang: [Strings translation](https://polylang.pro/doc/strings-translation/) - הקבוצה `plugins/atr-cookie-notice`.
3. בודקים כל שפה באתר בחלון פרטי.

שדה ריק משתמש בטקסט ברירת המחדל של התוסף, שכבר מוצג לפי שפת האתר.

= האם עוגיות אנליטיקה ושיווק מופעלות כברירת מחדל? =

לא. בטופס ההעדפות תיבות האנליטיקה והשיווק מתחילות לא מסומנות, והמבקר צריך לבחור בהן. עוגיות חיוניות תמיד מופעלות מאחר שהן נדרשות לתפקוד בסיסי של האתר. במצב פשוט אין מתגי קטגוריות.

= כמה זמן התוסף זוכר את הסכמת המשתמש? =

כברירת מחדל 365 ימים. משנים זאת באפשרויות מתקדמות ← "Cookie Expiry (days)". בתום התקופה הבאנר שואל שוב.

= איך מבקרים משנים או מבטלים את ההסכמה? =

מוסיפים את השורטקוד `[atr_cookie_notice_settings]` לעמוד מדיניות הפרטיות, לפוטר או לווידג'ט. הוא מציג קישור "Cookie settings"; לחיצה עליו מוחקת את הבחירה השמורה ומציגה את הבאנר מחדש. משנים את טקסט הקישור כך: `[atr_cookie_notice_settings text="הגדרות עוגיות"]`.

= מה בדיוק חוסם מצב מלא? =

עד שהמבקר מסכים, מצב מלא מנטרל את פונקציות Google Analytics (`gtag`, `ga`, `dataLayer.push`) בקטגוריית אנליטיקה ואת פונקציית Facebook Pixel (`fbq`) בקטגוריית שיווק, כך שקריאות מעקב לא נשלחות. הוא לא מונע מהדפדפן להוריד קובצי סקריפט של צד שלישי שהתבנית או תוסף אחר מוסיפים (למשל gtag.js או קונטיינר Google Tag Manager).

קוד מעקב שהתבנית או תוסף אחר מדפיסים לתוך הדף **לא נחסם אוטומטית**. כדי לעכב סקריפט לגמרי עד להסכמה, מסמנים אותו לתוסף במקום לטעון אותו ישירות:

`<script type="text/plain" data-consent="analytics" src="https://www.googletagmanager.com/gtag/js?id=G-XXXX"></script>`

לסקריפטים של פרסום משתמשים ב‑`data-consent="marketing"`. התוסף הופך אותם לסקריפטים רגילים רק אחרי שהמבקר הסכים לקטגוריה.

= האם יש דרך לבדוק את התוסף לפני הפרסום? =

כן, התוסף כולל מצב דיבוג המספק מידע מפורט בקונסולת הדפדפן, מה שמקל על בדיקה ופתרון בעיות במהלך הפיתוח.

= הבאנר או קבצים מעודכנים לא נטענים בחלק מהעמודים =

ראשית, נקו מטמון דפים ו‑CDN כרגיל (וגם מטמוני אופטימיזציה אם קיימים). אם הבעיה נמשכת, השתמשו ב"כלים" בדף הגדרות התוסף:

1. היכנסו להגדרות התוסף בלוח הבקרה
2. לחצו על "ניקוי מטמון ורענון משאבים" (מוסיף חותמת זמן ל‑CSS/JS ומנסה ניקוי מטמונים נפוצים)
3. רעננו עמוד פרונטאנד בחלון גלישה פרטית; כתובות המשאבים יכללו `?ver={גרסה}-{חותמת_זמן}`

אם משתמשים בתוספי מטמון, minification או אופטימיזציית JS, ייתכן שיהיה צורך להחריג את קבצי ה-JavaScript של התוסף מ:
* Minify/Combine
* Defer/Delay loading
* Async loading
* CDN delivery

נדרשת החרגת הקבצים הבאים:
* `/wp-content/plugins/atr-cookie-notice/public/js/atr-cookie-notice-public.js`
* `/wp-content/plugins/atr-cookie-notice/public/js/atr-cookie-notice-drag.js`
* `/wp-content/plugins/atr-cookie-notice/admin/js/atr-cookie-notice-admin.js`

לאחר ביצוע שינויים, השתמשו בכלי "ניקוי מטמון ורענון משאבים" ובדקו בחלון דפדפן פרטי.

= כיצד ניתן להתאים את תוכן הבאנר (טקסט וכפתורים)? =

בלשונית "תוכן" ניתן להחליף את ה‑HTML של טקסט הבאנר (`.scb-text`), אזור הפעולות (`.scb-actions`) בשני המצבים, ואת הפוטר (`.scb-footer`) במצב מלא. טוקנים זמינים:

- `{site_name}`, `{privacy_url}`, `{privacy_link}` (אלמנט קישור מלא עם כותרת עמוד מדיניות הפרטיות)
- במצב פשוט: `[ok_button]`, `[privacy_link]`
- במצב מלא: `[accept_all_button]`, `[reject_button]`, `[preferences_button]`

אבטחה: התוסף אוכף מזהי כפתורים נדרשים ומסנן את ה‑HTML.

= האם ניתן להתאים פריסט עיצוב? =

כן, אבל עליך לשמור את הפריסט תחילה לפני ביצוע שינויים מותאמים אישית. אם בוחרים פריסט עיצוב (בהיר, כהה, מינימלי או ניגודיות גבוהה) ורוצים להתאים אותו עוד יותר בלשונית עיצוב ומראה, בצעו את השלבים הבאים:

1. בחרו את הפריסט הרצוי מהתפריט הנפתח
2. הקישו **שמור הגדרות** כדי להחיל את הפריסט
3. בצעו את השינויים המותאמים אישית שלך בלשונית עיצוב ומראה
4. הקישו **שמור הגדרות** שוב כדי לשמור את ההתאמות שלך

אם תבצעו שינויים מבלי לשמור את הפריסט תחילה, תאבד את ערכי הפריסט.

= האם אני יכול לאפס הגדרות עיצוב לברירת מחדל? =

כן! בסעיף כלים של הגדרות התוסף, תמצאו כפתור "איפוס עיצוב לברירת מחדל" שמאפס רק את הגדרות העיצוב והמראה תוך שמירה על כל שאר ההגדרות ללא שינוי. הודעת אישור מונעת איפוסים בטעות.

= האם קיימת תצוגה מקדימה חיה? =

כן. בדף ההגדרות יש תצוגה מקדימה חיה צפה שמתעדכנת מיידית בעת שינוי השדות (כולל בוררי הצבעים והפריסטים). השינויים אינם משפיעים על האתר עד לשמירה.
